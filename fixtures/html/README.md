# HTML fixtures: landing page to PDF URL

These are trimmed copies of publisher pages. They are unit-test inputs for the Rust HTML-to-PDF-URL extractor and for the challenge and login-page classifier.

`expected.json` holds the test oracle in machine-readable form: base URL, expected PDF URL, alternates, URLs that must not be selected, and the signal that should win. This README gives the same information for people.

## How the files were made

- **Live:** an unauthenticated `curl` GET on 2026-10-20 with a Firefox 140 user agent. For entries marked "verified %PDF", a follow-up GET of the expected PDF URL with a cookie jar returned bytes starting with `%PDF-`.
- **Wayback:** most large publishers returned Cloudflare `403` (`cf-mitigated: challenge`) or an Akamai `403` to a plain HTTP client. For those, the raw original HTML came from the Internet Archive with `https://web.archive.org/web/<timestamp>id_/<url>`. The URLs in these pages were read from the HTML and were not fetched.
- **Trimming:** each page was cut down by `.ref/tools/trim-fixture.js`. The script keeps the `<title>`, the `citation_*`, `dc.*`, `prism.*`, `og:` and `wkhealth_*` meta tags, meta refresh tags (with any `<noscript>` wrapper), canonical and alternate links, PDF-like anchors (at most 14), PDF-like iframes, embeds and objects, and the ScienceDirect `pdfDownload` JSON fragment. It removes article text, scripts, styles, `citation_reference` and author lists past the second author. Hand-trimmed files say so in their header comment.
- **Resolving links:** resolve relative `href` values against the `base_url` in the table, which is the URL the page was served from. Decode `&amp;` before comparing.
